04 / SEO technical status

SEO predisposta ≠ SEO misurata

Componenti osservate

  • robots.txt e sitemap.xml presenti in più repository;
  • title, description, canonical e Open Graph nelle pagine controllate;
  • JSON-LD Schema.org di tipo Person, WebSite o WebPage nella home e in alcune pagine;
  • Netlify build configurato per pubblicare docs in Salvatore-Sinatra-Web.

Controlli ancora necessari

  • HTTP status e redirect di tutti i domini e canonical host;
  • confronto sitemap ↔ pagine reali ↔ canonical ↔ noindex;
  • link interrotti, pagine orfane, immagini e alt text;
  • validazione Schema.org, performance, mobile e accessibilità;
  • Google Search Console/Bing Webmaster Tools e analytics di traffico.

La SEO non può essere “iniettata” globalmente in tutti i motori con una singola configurazione Netlify: i file devono essere validi e pubblicati nel publish directory di ciascun progetto; l'indicizzazione dipende dai motori e i dati performance dipendono dagli strumenti analytics collegati.

05 / Audit e visualizzazione

Quadro analitico effettivo

Netlify Observability

La connessione Netlify ha restituito metadata dei progetti e stato del deploy; non sono ancora state interrogate le serie di richieste, top URL, status code o log per un progetto selezionato.

Misure possibili quando consultate: richieste edge, distribuzione status code, URL più richiesti, referrer, user agent, latenza e banda, nei limiti di conservazione del piano.

Search performance

Nessuna connessione Search Console/Bing/GA4 è stata letta in questa fase.

Non dichiarati: ranking, impressioni, clic organici, CTR, utenti, conversioni, backlink, competitor o keyword organiche misurate.

Il presente HTML è la visualizzazione referenziale iniziale. Non registra tracking, non invia dati a terzi e non modifica i sistemi di analytics. L'eventuale collegamento a strumenti analytics deve usare proprietà/account corretti e rispettare consenso e privacy.

07 / Piano di completamento

Sequenza controllata

  1. Questa pagina di riferimento: verificare HTML, link e leggibilità; decidere se inserirla nella Site Tree di main.
  2. Canonical & domini: verificare redirect apex/www e selezionare il dominio canonico per ogni sito.
  3. Audit per repository: controllare sitemap completa, robots, canonical, metadata, structured data e link.
  4. Pull request draft: riunire soltanto modifiche verificate in branch dedicati; mantenere production intatta fino all'approvazione.
  5. Analytics reali: leggere Netlify Observability per sito e integrare Search Console/GA4 solo quando le connessioni e le proprietà sono disponibili.
  6. Deploy: pubblicare preview, collaudare, quindi chiedere approvazione prima di qualsiasi merge o deploy production.
